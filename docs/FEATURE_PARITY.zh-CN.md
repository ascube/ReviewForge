# 跨平台功能对照

ReviewForge Desktop 2.1 已补齐对照原 Swift 实现与 Desktop 2.0.3 发现的功能缺口。Windows/macOS 共用同一套应用逻辑。按原要求，旧 Swift 数据迁移和 iPad 不属于本次范围。

| 流程 | 跨平台实现 |
|---|---|
| 远程 PR 审查 | 固定 head/base 和 PR 描述、缺失描述提示、默认缺陷＋可维护性＋NIT、范围选择、逐文件分段进度、继续剩余审查、分类过滤、差异定位、人工决策及独立发布批准。 |
| 本地审查 | 未提交修改、分支选择比较、最新提交、整个仓库；当前分支刷新、忽略规则、大文件分段及未审查原因；支持尚无提交的仓库，正确区分首个提交和浅克隆缺失历史。 |
| 本地修复 | 生成和应用前核对原审查快照，逐文件编辑建议，保留原换行与 EOF，写入前独立备份，失败回滚，恢复预览与后续修改保护，丢弃修复草稿。 |
| 反馈处理 | 完整分页评论、resolved/outdated 标识、隐藏已解决、从本地或远端准备隔离工作区、外部编辑和应用内文件编辑/丢弃。 |
| 验证和推送 | 验证结果绑定代码，预览提交身份/空白字符问题，批准指纹、amend 明确确认、force-with-lease、推送尝试持久化、中断恢复，以及按提交祖先关系同步外部推送。 |
| 回复草稿 | 推送前后均可生成，基于所选评论和实际代码快照；AI 建议与人工正文分开，包含依据/限制，支持单条或批量生成、明确采纳/拒绝，失败批次保留已有草稿。 |
| 回复发布 | 预览确切已推送提交和差异；发送回复与解决可分别选择；批准门槛、账号和原评论重验、返回回复身份及 resolved 状态验证、不确定结果恢复；后续本地修改不混入已确认代码。 |
| Review 发布 | 自己的 PR/pending review 检查、账号及冻结 PR/描述核对、批准指纹、持久化发送意图、返回 commit/作者/状态验证、按 marker 核实，不盲目重复发送。 |
| 认证 | GitHub 设置 → 环境变量 → CLI，显示账号与来源；Copilot 独立认证；连接失败清空模型列表；IP/SSO/认证/限流/TLS/网络/服务端/运行时双语诊断。 |
| 报告和 Markdown | 完整本地 Markdown 报告含逐文件评估、发现/决策和遗漏原因；远程 JSON 导出；预览/复制原文、代码块复制、扩展后缀及原始 AI 意见保留。 |
| 数据与恢复 | SQLite、归档/恢复/删除保护、数据目录副本验证、目录不可用保护、工作区/恢复路径更新、保留不确定发布记录。 |
| 语言与引导 | 首次启动默认英文，持久化简体中文选择，新流程双语，离线示例、关于/作者说明、设置与源码构建指南。 |

界面布局不要求逐像素复制 Swift。验证命令改用可执行文件及参数列表，Git/Copilot 运行时直接随安装包提供。

自动化测试使用临时 Git 仓库和模拟 GitHub 写操作；真实 Copilot 验证仅使用合成代码和评论，GitHub 请求/写入被禁止。双语界面和最小窗口已检查。具体测试、平台构建和验收边界见 [VALIDATION.md](../VALIDATION.md)。这不等于所有组织权限或项目工具链均已逐一验证。

恢复副本属于本地项目数据，不会随应用发行上传。如恢复会覆盖后续外部修改，应用会保留修改和副本，要求先处理冲突。
