## 安装

从 [GitHub Releases](https://github.com/ascube/ReviewForge/releases/latest) 下载。当前提供 macOS Apple Silicon（arm64）、macOS Intel（x64）和 Windows x64，无 Linux 安装包。建议使用 macOS 13+ 或 Windows 10/11 x64；内置 Git LFS 要求 macOS 13+。已在 Apple Silicon 实际操作验证；各平台原生 CI 构建与运行时结果见 Actions，Intel 和 Windows 的交互界面及安装验收仍待人工完成。

- **macOS：** 打开 DMG，拖入 Applications 后启动；ZIP 需先完整解压。
- **Windows：** EXE 安装到当前用户目录；便携 ZIP 必须整体解压，再运行 ReviewForgeDesktop.exe，不要单独移动 EXE。
- **签名状态：** 当前没有 Apple Developer ID 公证或 Windows Authenticode 发布者签名。请遵循设备和组织安全策略，不要关闭安全防护来安装。
- **校验：** 下载 SHA256SUMS。macOS 使用 `shasum -a 256 文件名`，Windows PowerShell 使用 `Get-FileHash -Algorithm SHA256 文件名`，核对相应校验值。校验值用于检测文件是否变化，不等同于签名。
- **升级：** 退出应用再替换或安装新版，建议先备份数据目录。草稿与应用分开保存；不迁移旧 Swift 版数据。

## 首次启动与认证

无论系统语言如何，首次启动均为英文。在 **Settings → Language → 简体中文** 切换并自动保存；不会翻译用户内容或路径。

GitHub 和 Copilot 凭据分别配置。访问仓库需要对应权限，发布审查、推送代码、解决线程还需要相应写权限；Copilot 需要有效使用权限。已配置的 Copilot 凭据优先，否则可复用 GitHub CLI 登录。其他编辑器中的登录不会自动导入。

使用 **检查 GitHub** 和 **检查 Copilot / 加载模型** 验证。企业 SSO、IP 白名单和 VPN 要求仍然适用。凭据通过系统加密保存；只在应用设置或提供商官方登录流程中输入，禁止放入 PR 描述或公开 Issue。若出现钥匙串提示，请先确认请求来自 ReviewForge。

## 远程 PR 审查

1. 在 **远程审查** 粘贴 github.com PR 链接并导入。
2. 检查捕获的 PR 描述，缺失或只含模板注释会提示；其中的产品要求会作为审查依据。
3. 选择默认“缺陷 + 可维护性 + NIT”或“仅缺陷”。NIT 是通常不阻塞合并的命名、格式、可读性等小建议。
4. 开始分析，查看逐文件和分段进度。中断后可继续剩余部分，不支持或不可读取的文件会显示原因。
5. 对照 diff 检查每条发现，分类筛选、修改措辞，必要时从 diff 首列添加手工发现；逐条明确包含或排除。
6. 编辑摘要并选择评论、批准 PR 或请求修改。批准 PR 与批准“发布操作”不是一回事。
7. 预览发布 → 批准审查 → 发布。远程代码或描述改变会使原批准失效；分析完成不会自动发布。

每轮最多包含 50 条行内发现，GitHub 自身 patch/API 限制仍可能导致覆盖不足；批准 PR 需要完整覆盖。发布状态不确定时先核实，避免重复提交。

## 本地仓库审查和修复

1. 选择本地 Git 仓库，自动读取当前分支与 HEAD，不会切换分支。
2. 选择未提交修改、分支对比、最新提交或整个仓库。对比分支从列表选择，不会隐式 fetch。
3. 可指定子目录，捕获冻结快照。之后修改了代码，需要重新捕获。
4. 分析并查看分类报告。匹配忽略规则的文件不参与审查；二进制、非 UTF-8、符号链接、子模块和不可读文件单独列明。大文件分段，不再使用 160 个文件或 500 KB 总量限制静默遗漏。
5. “修复所有问题”针对未排除的问题生成本地提案，逐项预览、编辑，明确应用后才写入文件。应用前核对原始内容，并保留原有换行约定。
6. 运行项目测试，查看 Git diff；再次审查时捕获新快照。

## 处理反馈、推送和回复

1. 打开 **处理反馈** 并加载 PR 评论。已解决、已过期会标注；隐藏已解决也会过滤已选中的 resolved 线程。
2. 选择评论，从本地仓库复制或克隆隔离工作区，原始 checkout 不受影响。
3. Copilot 生成修复提案，也可用外部编辑器打开工作区修改。先预览、编辑，再明确应用。
4. 用可信可执行文件和 JSON 参数数组验证，不会隐式运行评论里的 shell 命令；项目工具链需要自行安装。
5. 外部 commit、amend 或 push 后同步状态，重新查看并批准代码。历史改写需明确批准，推送使用预期远程 SHA 租约保护。
6. 推送前后都可按评论与真实代码差异生成回复草稿，逐条修改，不要声称运行了未执行的测试。
7. 只有确认干净的本地 HEAD 已在 PR 来源分支上，才允许预览并批准回复／解决计划后发布。结果不确定时先核实之前的回复。

## 数据与隐私

设置中的本地数据目录可查看、复制更换。支持归档、恢复和 Markdown 导出；删除草稿不会删除原仓库。备份时关闭应用；系统加密凭据可能不能迁移到其他机器。

只有请求 AI 操作时，选定代码和上下文才发给 GitHub Copilot。请遵循仓库所有者的 AI 使用规则。Markdown 预览不加载远程图片、不执行原始 HTML。模型不具有终端、提交、推送或发布工具。

## 常见问题

- **认证失败：** 检查 Copilot 凭据／GitHub CLI 当前账号、订阅及 SSO；企业 IP 限制需要连接批准的网络。
- **有文件未审查：** 查看具体原因，继续剩余部分，或重新捕获旧快照。
- **HEAD 改变：** 同步、预览并重新批准；保留本地修改。
- **回复无法发布：** 确认代码已推送且工作区干净，再同步、预览和批准回复。
- **发布状态不确定：** 核实结果，不要重复点击发布或删除记录。
- **Windows 问题：** 提交系统版本、架构、应用版本及脱敏错误；原生验收尚未完成。
